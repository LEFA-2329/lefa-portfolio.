# Saved drafts and question progress

`/learn/#saved-work` lists saved items and links back to the relevant lesson, task, activity or editor. A status banner shows normal saving or a storage warning. Work saves synchronously on input/change so a refresh immediately after typing can restore it. Saved items include lesson tabs and question position, unsubmitted quiz choices, graded attempts, partial debugging selections, debugging hints/solutions, lesson practice drafts, task-library drafts/attempts, interactive exercise selections/order/hints/attempts, diagram editor source/type and tracer source/example selection.

Runtime tracer inputs and execution history are not persisted. A reopened tracer restores code only and requires Prepare and fresh input. Data belongs to a browser profile and site origin, with no account, server transmission or cross-device synchronisation. People sharing one browser profile share its saved work. Private browsing, clearing site data and storage quotas can remove or prevent saving.

`work-store.mjs` uses separate versioned `logiclab-work-v1:` records with timestamps. Records have a size limit, parse guards and consumer-specific field validation. Lesson pass states are recomputed from validated answer choices and submission flags on restore. Empty or unsubmitted work does not unlock answers. A failed write leaves the current in-memory work open and keeps earlier persisted records intact. The status banner tells students to copy work before leaving when storage is unavailable or full. Per-record keys prevent editing one lesson from replacing another record. Edits to the same record in multiple tabs use the last successful save, so simultaneous editing of that same item should be avoided.

Clear saved work requires confirmation in the UI and removes only this application's work-record prefix. Completed-lesson marks in `logiclab-progress-v1` remain available to the existing separate reset control. No other site's/app's localStorage keys are cleared. Reloading after clearing also discards stale in-memory drafts.

Validation: `node tests/logiclab-work-store.test.mjs` covers restoration with a fresh store, separate keys, corrupt and unsupported records, blocked/full storage, strict answer validation, gate preservation, size bounds and scoped clearing. Existing activity, NUM, grid, lesson and revision checks pass. Browser checks cover immediate refresh after an unsubmitted selection/draft, graded quiz position, debugging selections and hints, interactive choices and ordering, editor source/type, fresh tracer state, clear-dialog cancellation, and closing/reopening a tab. The storage-failure paths are tested with injected fake storage, not by changing the user's browser settings.
